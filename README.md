# CartWise Playwright QA Portfolio

An independent, AI-assisted testing project for a fictional shopping app. It demonstrates a reusable Page Object Model, UI regression scenarios, direct API testing, negative cases and server-side price validation. It contains no employer systems, client data, work credentials or production payment integration.

**Status:** 15 API tests and 8 unit tests passed in the build environment. The 14 UI scenarios are authored and configured for Chromium, Firefox, WebKit and mobile Chromium, but have not been executed here because browser downloads failed. See `docs/VALIDATION.md`. Do not present configured browser coverage as passed coverage.

## Quick start on Windows

Install Node.js 22 or newer, extract this folder, open PowerShell in it, then run:

```powershell
npm ci
npx playwright install
npm run test:unit
npm run test:chromium
npm run test:api
npm run report
```

Run the whole configured browser matrix with `npm test`. On Linux, use `npx playwright install --with-deps` when browser system dependencies are missing. HTML reports are generated by Playwright; traces, screenshots and videos are retained on failure.

To browse the app without tests:

```powershell
npm start
```

Open http://127.0.0.1:4173. Stop with Ctrl+C. Use fictional contact details only. No real payments, authentication or messages exist. Orders are returned in memory and not stored. The cart persists in that browser's local storage; the coupon does not persist across reload.

## What the project demonstrates

| Area | Evidence |
| --- | --- |
| UI automation | Search, filters, stock limits, quantities, removal, coupon handling, persistence and checkout |
| Page Object Model | `tests/pages/store.page.mjs` centralizes user actions |
| API testing | Catalog contract, exact totals, malformed payloads and negative boundaries |
| Data integrity | Server uses integer paise and authoritative prices, ignoring caller-supplied prices |
| Resilience | UI test aborts the order API and verifies a recoverable error with cart preserved |
| Browser configuration | Desktop Chromium/Firefox/WebKit and a mobile Chromium viewport |
| CI | GitHub Actions workflow runs tests and uploads reports when published |

This implementation uses **JavaScript**, not Java or Selenium. It is a new learning/demo asset, not evidence that Monica used JavaScript professionally or built this in a past employer role. A Selenium/Java companion can be added separately after this project is reviewed.

## Limits and design decisions

- The app is purpose-built for testing; passing tests do not prove quality of a real customer system.
- No authentication, inventory reservation, order database, email delivery or payment provider is implemented.
- API tests intentionally verify server validation even when the UI prevents an action.
- Expected totals in tests are independent constants; tests do not call the application's pricing function to compute expected results.
- Browser contexts isolate UI tests. API order responses do not mutate inventory or create persistent records.
- Auto-retrying assertions are used; there are no arbitrary sleep calls.
- GitHub Actions is included but has not run in a public repository yet.
